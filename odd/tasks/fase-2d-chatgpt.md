# Fase 2D — Iniciar sesión con ChatGPT

Eva can use the user's ChatGPT Plus/Pro plan through OpenAI's "Sign in with ChatGPT" (open-source/local flow, preview), with several saved accounts and a picker.
Branch: `feat/fase-2d-chatgpt` (from `main` after the 2C merge, PR #4). Python 3.11, Flet 1.1.2, Windows dev machine (Git Bash). Tests: `venv/Scripts/python.exe -m pytest -q` (412 passed, 2 skipped at start).

## Specs

Plan quote (docs/plan-de-trabajo.md, Fase 2) is verbatim; the protocol facts come from OpenAI's docs (L3); the rest is the parent's technical design. User-facing text: neutral Spanish with "tú". Never log, show or put in URLs/errors any token, code, verifier or key.

- S1 (plan): "Implementar "Iniciar sesión con ChatGPT" en `auth.py` (OAuth con PKCE): la app abre el navegador, el usuario entra con su cuenta y la app usa su plan Plus o Pro."
  Design (module `app/auth_chatgpt.py`, separate from OpenRouter's `app/auth.py`):
  `iniciar_sesion_chatgpt(host_id, client_id=None, id_token_hint=None, login_hint=None, subject_esperado=None, pedir_consentimiento=False, abrir_navegador=webbrowser.open, al_sin_navegador=None, timeout=300, cancelado=None, http_client=None) -> ResultadoSesion`.
  - Loopback listener on `127.0.0.1` (never `localhost`), port 1455 if free else any free port, path `/auth/callback`; listener started before the browser opens; same exact `redirect_uri` in authorize and exchange.
  - Fresh `state`, `nonce`, PKCE verifier (S256, base64url without padding) per attempt.
  - Authorize URL `https://auth.openai.com/api/accounts/authorize` with: `client_id` (`dynamic_agent_client` for a new account, else the saved issued id), `agent_name_hint=Eva` (new registration only), `ext_agent_host_id`, `id_token_hint`/`login_hint` (reauthorization only, when given), `response_type=code`, `redirect_uri`, `scope=openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, `resource=https://api.openai.com/v1`, `state`, `nonce`, `code_challenge_method=S256`, `code_challenge`, and `prompt=consent` only when `pedir_consentimiento`.
  - Callback: validate `state`; `error=access_denied` → `ErrorAuth("No autorizaste a Eva en ChatGPT.")` without exchanging; other OAuth error → `ErrorAuth("ChatGPT no autorizó el inicio de sesión.")`; a new registration without `client_id` → `ErrorAuth("ChatGPT no completó el registro de Eva. Inténtalo de nuevo.")`; on reauthorization a different `client_id` → reject with the same not-authorized message. Never save `dynamic_agent_client` as the issued id. Callback page: "Listo. Ya puedes volver a Eva." (or the error text), never the code.
  - Exchange: form POST `https://auth.openai.com/api/accounts/oauth/token` with `grant_type=authorization_code`, issued `client_id`, `code`, `code_verifier`, same `redirect_uri`, `resource`; no secret. `invalid_grant` → `ErrorAuth("El código de ChatGPT ya no sirve. Inicia sesión de nuevo.")`; other errors → `ErrorAuth("ChatGPT rechazó el inicio de sesión: <detalle>")`; network → `ErrorAuth("No pude conectarme con ChatGPT. Revisa tu conexión a internet.")`.
  - ID token: verify signature with OpenAI's JWKS (`jwks_uri` from `https://auth.openai.com/.well-known/openid-configuration`, fetched with the injectable `http_client`), `iss=https://auth.openai.com`, `aud` = issued client id, `exp`, and the saved `nonce`, using PyJWT; failure → `ErrorAuth("No pude validar la identidad de tu cuenta de ChatGPT.")`. `subject_esperado` given and different `sub` → `ErrorAuth("Iniciaste sesión con otra cuenta de ChatGPT. Elige esa cuenta o agrégala como nueva.")`.
  - `ResultadoSesion`: `client_id, email, subject, id_token, access_token, refresh_token, expira` (epoch seconds = now + `expires_in`), `scopes` (from the token response `scope`). Missing `chatgpt.tokens.use.direct` is NOT an error (the caller marks plan use disabled).
  - Cancel (`cancelado` Event) honoured until it returns, including after the exchange; no browser: same behavior as OpenRouter S8 (`al_sin_navegador(url)` keeps waiting, else immediate `ErrorAuth("No pude abrir el navegador. Revisa que tengas uno instalado e inténtalo de nuevo.")`). The listener always closes.
  - `renovar(client_id, refresh_token, http_client=None) -> Tokens(access_token, refresh_token, expira, scopes)`: form POST `grant_type=refresh_token`, issued `client_id`, `refresh_token`, `resource`; no `scope`. Codes `invalid_grant`, `invalid_refresh_token`, `token_expired`, `refresh_token_expired`, `refresh_token_invalidated`, `refresh_token_reused` → `ErrorSesionVencida("Tu sesión de ChatGPT venció. Vuelve a iniciar sesión en Ajustes.")`; network/5xx → `ErrorAuth` (credentials kept).
  - `cerrar_sesion(client_id, refresh_token, http_client=None) -> bool`: POST to the discovery `revocation_endpoint` with `token`, `token_type_hint=refresh_token`, `client_id`; HTTP 200 (even empty) → True; network/5xx retried up to 3 times with short backoff, then False; never raises for these.
- S2 (user decision L4, L5): tokens stored in an encrypted file; several accounts.
  Design (module `app/cuentas_chatgpt.py`): `CuentaChatGPT` dataclass (`id`, `email`, `subject`, `client_id`, `id_token`, `access_token`, `refresh_token`, `expira`, `scopes`, `guardada`) with `plan_habilitado` (`"chatgpt.tokens.use.direct" in scopes`) and `conectada` (has access and refresh tokens). `id` is a stable short hash of `subject` + `client_id`. `AlmacenCuentas(ruta=None)` keeps one file `carpeta_datos()/chatgpt.bin` encrypted with Fernet; the Fernet key lives in the keyring (`secretos`, username `chatgpt-cifrado`), created on first save. API: `host_id()` (a `urn:uuid:<uuid4>` created once and persisted in the same file), `listar()`, `obtener(id)`, `guardar(cuenta)` (insert or replace by id), `actualizar_tokens(id, tokens)` (access, refresh, expiry and scopes replaced together), `olvidar_tokens(id)` (sign-out: clears the three tokens, keeps the registration and host id), `borrar(id)`. Writes are atomic (temp file + `os.replace`, 0600 on POSIX). A keyring failure → `ErrorSecretos` (fail closed). A file that cannot be decrypted or parsed → `ErrorCuentas("No pude leer tus cuentas de ChatGPT guardadas.")` and the file is never overwritten or deleted by a read. A thread lock serializes access; `renovar` for the same account is serialized by the caller (S4).
- S3: ChatGPT client (module `app/llm/chatgpt_client.py`) `ClienteChatGPT(modelo, obtener_token, http_client=None)` implementing `ClienteLLM`; `nombre="ChatGPT"`, `proveedor="chatgpt"`.
  - `listar_modelos() -> list[tuple[str, str]]`: GET `https://api.openai.com/v1/models` with `Authorization: Bearer <token>`; read the `models` array, keep `visibility == "list"`, keep server order, return `(slug, display_name)`.
  - `responder(mensajes)`: POST `https://api.openai.com/v1/responses` with `stream: true`, `store: false`, `model`, `instructions` = all system messages joined with "\n\n", `input` = the user/assistant messages in order as `{"role", "content"}` items (never a system item); none of the unsupported fields. Yield `response.output_text.delta` text; success only on `response.completed`.
  - Errors (`ErrorLLM`, exact text): before the stream 401 or code `subscription_sharing_invalid_user` → "ChatGPT no aceptó tu sesión. Vuelve a iniciar sesión en Ajustes."; `subscription_sharing_user_not_eligible` (403) → "Tu cuenta de ChatGPT no puede usar su plan en Eva (hace falta Plus o Pro)."; `subscription_sharing_usage_limit_exceeded` (429, also as `response.failed` mid-stream) → "Llegaste al límite de uso de tu plan de ChatGPT. Revísalo en https://chatgpt.com/settings/usage"; 503 or `subscription_sharing_usage_unavailable`/`subscription_sharing_user_unavailable` → "ChatGPT no está disponible en este momento. Inténtalo más tarde."; other HTTP errors → "ChatGPT devolvió un error: <detalle>" (detail from `error.message`, or `detail`, with tokens masked); connect error → "No pude conectarme con ChatGPT. Revisa tu conexión a internet."; timeout before the answer → "ChatGPT tardó demasiado en responder. Inténtalo de nuevo."; stream cut, `response.incomplete` or ended without `response.completed` → "Se perdió la conexión con ChatGPT mientras respondía. Inténtalo de nuevo."; other `response.failed` → "ChatGPT devolvió un error: <code>". `obtener_token` raising `ErrorLLM` is passed through. `max_retries=0`, chat timeout 120 s, listing 10 s.
- S4: settings and chat with several accounts (UI, wiring).
  Design: `PROVEEDORES` gains `chatgpt` ("ChatGPT", cloud, account-based, no API key field). Choosing it shows: a "Cuenta" dropdown (saved accounts by email; duplicates disambiguated as "email (2)"; plus "Agregar cuenta…"), a "Continuar con ChatGPT" button (new registration for "Agregar cuenta…", reauthorization with `client_id`, `id_token_hint`, `login_hint`, `subject_esperado` for a saved one; second click cancels; manual-URL path as S8 of 2C), "Cerrar sesión" (calls `cerrar_sesion`, then `olvidar_tokens`; when revocation is not confirmed shows "Cerré tu sesión en Eva, pero no pude confirmarlo con OpenAI. Puedes desconectar Eva en la configuración de ChatGPT."), and the text "Uso del plan: chatgpt.com/settings/usage". A signed-in account without plan permission shows "Tu cuenta inició sesión, pero no autorizó usar tu plan de ChatGPT en Eva." and the button "Permitir usar mi plan" (reauthorization with `pedir_consentimiento=True`). Models load from the selected connected account (display name shown, slug saved). "Guardar" stores `proveedor=chatgpt`, `modelo=<slug>`, `extras["chatgpt_cuenta"]=<id>` and `extras["respaldo"]={"proveedor": "chatgpt", "modelo": <slug>, "cuenta": <id>}`. The chat connects with `ClienteChatGPT`, label "ChatGPT · <display name or slug>"; the token provider refreshes (via `renovar`, serialized per account, `actualizar_tokens`) when the access token expires within 120 s; `ErrorSesionVencida` clears the tokens (`olvidar_tokens`) and surfaces its message. The memory-extraction fallback (2C S5) accepts a ChatGPT `respaldo`. Existing providers keep their behavior.
- S5: requirements pin `PyJWT[crypto]` (and its `cryptography`); README and plan updated; every new user message tested through the public interface; independent verify (Risk item 2 credentials, item 5 dependencies); native review; live test with the user's Plus/Pro account.
