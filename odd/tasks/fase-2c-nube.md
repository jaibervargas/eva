# Fase 2C — Modelos en la nube y cuentas

Eva can chat with OpenAI, Claude and Gemini using the user's API key or an OpenRouter account, keeps keys in the OS keyring, and falls back to the cloud for memory extraction when the local model fails.
Branch: `feat/fase-2c-nube` (stacked on `feat/fase-2b-engram`, not yet merged to `main`). Python 3.11, Flet 1.1.2, Windows dev machine (Git Bash). Tests: `venv/Scripts/python.exe -m pytest -q` (218 passed, 2 skipped at start).

## Specs

Plan quotes (docs/plan-de-trabajo.md, Fase 2) are verbatim; decisions below them are the parent's technical design. User-facing text uses neutral Spanish with "tú", like the existing messages ("Revisa…", "Descarga…").

- S1 (plan): "Implementar `llm/cloud_client.py` (OpenAI, Claude y Gemini con clave de API), movido desde la Fase 1."
  User decision (L4): Claude uses the native `anthropic` SDK; OpenAI, Gemini and OpenRouter use the existing `openai` SDK with their official OpenAI-compatible base URLs.
  Design: `app/llm/cloud_client.py` implements `ClienteLLM` (`responder(mensajes) -> Iterator[str]`, streaming) plus `listar_modelos() -> list[str]` for providers `openai` (https://api.openai.com/v1), `gemini` (https://generativelanguage.googleapis.com/v1beta/openai/), `openrouter` (https://openrouter.ai/api/v1) and `anthropic` (native SDK; all system messages joined with "\n" into `system`; explicit `max_tokens`). `max_retries=0`, chat timeout 120 s, model listing 10 s; injectable `http_client` for tests. Model lists keep only chat models (OpenAI: drop embedding/tts/whisper/dall-e/image/audio/realtime/transcribe/moderation/search ids; Gemini: ids containing "gemini", "models/" prefix removed; Anthropic and OpenRouter: all). Every failure raises `ErrorLLM` with a message for the user naming the provider: invalid key (401/403) → "La clave de <Proveedor> no es válida. Revísala en Ajustes."; no connection → "No pude conectarme con <Proveedor>. Revisa tu conexión a internet."; rate limit / no credit (429) → "<Proveedor> rechazó el pedido por límite de uso o falta de saldo. Inténtalo más tarde."; lost mid-answer → "Se perdió la conexión con <Proveedor> mientras respondía. Inténtalo de nuevo."; other API errors → "<Proveedor> devolvió un error: <detalle>". A factory `conectar_nube(proveedor, modelo_guardado, clave)` lists models and picks the saved one or the first (like `local_client.conectar`); no key → `ErrorLLM("Falta la clave de <Proveedor>. Agrégala en Ajustes.")`.
- S2 (plan): "Guardar el token de la cuenta y las claves de API con la librería `keyring` (el almacén seguro del sistema operativo), nunca en texto plano dentro de `config.json`."
  Design: `app/secretos.py` with `leer_clave(proveedor) -> str | None`, `guardar_clave(proveedor, clave)`, `borrar_clave(proveedor)`; keyring service "Eva", username = provider id. Keyring backend failures raise `ErrorSecretos` with a user message ("No pude usar el almacén seguro del sistema: <detalle>"); `leer_clave` on a failing backend raises too (never returns a key from anywhere else). Keys never appear in `config.json`, logs or error messages. Tests use an in-memory keyring backend, never the real OS store.
- S3 (plan): "Crear la pantalla de ajustes (proveedor: Ollama, LM Studio o nube; modelo, elegido de la lista de modelos instalados; forma de acceso a la nube: clave de API o cuenta (ChatGPT u OpenRouter); voz) que guarda en `config.json`."
  Scope (L3, L5): this block adds the cloud providers and access by API key or OpenRouter account; the ChatGPT account goes to block 2D and the voice to Fase 4.
  Design: `PROVEEDORES` gains `openai` ("OpenAI"), `anthropic` ("Claude"), `gemini` ("Gemini"), `openrouter` ("OpenRouter"), each marked as cloud. The settings dialog shows all six; choosing a cloud provider shows a password field "Clave de API" (empty field with hint "Clave guardada" when one exists keeps the saved key), a "Borrar clave" button and, for OpenRouter only, "Iniciar sesión con OpenRouter". Models load from the provider using the typed or saved key (off the UI loop, latest load wins, as today). "Guardar" stores a typed key in the keyring (S2) and provider + model in `config.json`; a keyring failure shows the error and keeps the dialog open. The chat connects through one factory for local and cloud providers and shows "<Proveedor> · <modelo>". Existing local behaviour (LM Studio/Ollama, unknown provider → LM Studio) must not change.
- S4 (plan): "Para Claude y Gemini, ofrecer clave de API o "Iniciar sesión con OpenRouter" (OAuth con PKCE, sin necesidad de registrar la app): el usuario entra con su cuenta de OpenRouter, la app recibe una clave ligada a esa cuenta y el usuario fija su propio límite de gasto. No se usa la suscripción Claude Pro/Max ni Google AI Pro, porque sus términos no lo permiten en apps de terceros."
  Design: `app/auth.py` `iniciar_sesion_openrouter(abrir_navegador=webbrowser.open, timeout=300, http_client=None) -> str`: new `code_verifier` per attempt, S256 `code_challenge`, random `state`; loopback HTTP server on 127.0.0.1 with a free port, `callback_url=http://localhost:<port>/callback`; opens `https://openrouter.ai/auth?callback_url=…&code_challenge=…&code_challenge_method=S256&state=…`; on `/callback` checks `state` and `code`, answers a small HTML page "Listo. Ya puedes volver a Eva."; exchanges with `POST https://openrouter.ai/api/v1/auth/keys` `{"code", "code_verifier", "code_challenge_method": "S256"}` and returns `key`. Failures raise `ErrorAuth` with a user message: timeout ("No se completó el inicio de sesión con OpenRouter a tiempo. Inténtalo de nuevo."), denied/missing code or wrong state ("OpenRouter no autorizó el inicio de sesión."), exchange error ("OpenRouter rechazó el inicio de sesión: <detalle>"), no connection. The server always closes. Can be cancelled from the UI. The key is saved with `secretos.guardar_clave("openrouter", key)` and the verifier/code never logged.
- S5 (plan): "Después de cada respuesta, guardar en Engram los datos importantes del usuario (nombre, gustos, decisiones). Si el modelo local no detecta bien qué guardar, usar el de la nube solo para esa tarea."
  User decision (L4): "Solo si el local falla" — if the local model's output cannot be read as JSON or the local model raises an error, and a cloud provider with a saved key exists, retry once with the cloud.
  Design: `extraer_hechos` distinguishes unreadable output from a valid `[]`. The settings remember the last saved cloud provider and model as the extraction fallback (`config.json`: `"respaldo": {"proveedor", "modelo"}`, no key). When the chat provider is local and the fallback's key exists, `MemoriaUsuario.aprender` retries once with that cloud client; a valid `[]` from the local model never calls the cloud; a cloud failure saves nothing and never raises. When the chat provider is already a cloud one, there is no second attempt.
- S6: requirements pin `anthropic` and `keyring`; the plan checkboxes and README are updated; every new user message is covered by a test through the public interface.

- S7 (review advisories, user chose "1" = fix them as proposed): one small test-first commit.
  (a) R1-001/R3-003/R4-cancel-during-exchange: cancelling is honoured until the key is saved: `iniciar_sesion_openrouter` checks `cancelado` after the code exchange and raises `ErrorAuth("Se canceló el inicio de sesión con OpenRouter.")` (the minted key is discarded, never returned); `ajustes` also re-checks the event before `guardar_clave` and never saves when it is set (dialog closed, provider changed or second click).
  (b) R3-004/R4-loopback-ipv4-only: the callback URL uses `http://127.0.0.1:<port>/callback` (the address the server binds).
  (c) R3-005: an `OSError` while starting the loopback server raises `ErrorAuth("No pude preparar el inicio de sesión con OpenRouter: <detalle>")`.
  (d) R3-001: when `abrir_navegador` returns False (or raises), fail at once with `ErrorAuth("No pude abrir el navegador. Abre esta dirección para iniciar sesión con OpenRouter: <url>")` and the server closes.
  (e) R3-006: read/write/pool timeouts from a reachable provider give "<Proveedor> tardó demasiado en responder. Inténtalo de nuevo." (before the answer starts) instead of the no-connection message; connect errors keep "No pude conectarme con <Proveedor>. Revisa tu conexión a internet."; a timeout mid-answer keeps the lost-connection message.
  R3-002 (first bad callback aborts) stays as is by design.

- S8 (T6 review advisory R3-001/R4-001, user chose "1.A": keep the server waiting and show the URL so the manual path works).
  Design: `iniciar_sesion_openrouter(..., al_sin_navegador: Callable[[str], None] | None = None)`. When `abrir_navegador` returns False or raises: if `al_sin_navegador` is given, call it with the auth URL and keep waiting for the callback (same timeout and cancel as usual; the server stays open; the exchange works when the user opens the URL by hand); if it is not given, raise `ErrorAuth("No pude abrir el navegador. Revisa que tengas uno instalado e inténtalo de nuevo.")` at once and close the server. The settings dialog passes a callback that shows, in `estado` (gray, selectable text), "No pude abrir el navegador. Abre esta dirección para iniciar sesión con OpenRouter: <url>"; the button stays as "Cancelar inicio de sesión". The S7(d) message that promised a manual path with the server already closed is removed. Advisories R1-001/R3-002 (key not revoked on cancel) and R1-002/R3-003 (tiny cancel race) stay as they are (no user change requested).
